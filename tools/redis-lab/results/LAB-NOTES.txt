Lab-script fixes
1. lib.sh cmpconf: used `redis-cli --no-raw ... | sed -n 2p`, which returns `2) "value"`, so every key
   was reported as DIFF. Now uses raw output. After the fix: standalone and sentinel 0 DIFF; cluster only `databases`.
2. lib.sh x(): REDISCLI_AUTH was also sent to Sentinel (no password) -> "AUTH failed" noise on every
   `redis-cli -p 26379` line. Added a redis-cli wrapper inside the container that unsets REDISCLI_AUTH for -p 263xx.
   The printed commands are unchanged.
3. 10-standalone: `REDISCLI_AUTH= redis-cli` still sends AUTH with an empty password (AUTH failed / WRONGPASS lines).
   Changed to `env -u REDISCLI_AUTH redis-cli`.
4. 10-standalone: the 8.10.2 build ran `make` (= build with bundled modules), which failed (rc=2) on
   redisbloom/redisearch/redisjson/redistimeseries. Changed to `make ... build redis` (core only), rc=0.
5. 10-standalone: `diff` is not installed in rocky9-base, so redis.conf-template-diff.txt was empty.
   The helper now installs diffutils quietly before diffing (not printed in the log).
6. 10-standalone: `DEBUG POPULATE` and `DEBUG SLEEP` are rejected (enable-debug-command defaults to no),
   so the 100k-key load did nothing (dbsize 1) and no slowlog entry was created. Replaced with a
   pipelined SET of 100000 keys (100-byte values) and a ~200 ms Lua busy loop (`for i=1,150000000`).
   (A Lua loop on redis.call("TIME") was tried first: TIME is frozen inside a script, so it ran 5 s. Not used.)
7. 10-standalone: redis-benchmark progress lines used \r; output is now filtered to the final "requests per second" lines.
8. 20-sentinel: fixed `sleep 8` / `sleep 12` replaced by polling (wait_until), with the wait time printed:
   after SENTINEL FAILOVER, rs1 was still master with 0 replicas and had no CONFIG REWRITE block 8 s later;
   after unpause, the old master's link was still down at 12 s.
9. 20-sentinel: master() always asked rs3's Sentinel; when rs3 was the paused master it returned nothing
   and the rest of test 2 ran against an empty node name. Now asks any Sentinel that responds.
10. 20-sentinel test 2: after the new master is elected, the script now waits until
   min_slaves_good_slaves >= 1 and writes again. In one earlier run the first write after failover
   returned "NOREPLICAS Not enough good replicas to write" (min-replicas-to-write 1, replica still
   reconfiguring); in the final run the first write succeeded straight away.
